## 4. 设计思路

### 4.1 为什么换 OS4 底包

用户手机实际运行 OS4.0.2.0.XOLCNXM（Android 17），vendor / system 都是新的。继续用 OS3 recovery 会让 vendor 的 `wpa_supplicant` 与 recovery 的 `/system/lib64` 版本错位（`libvndksupport` / `libdl_android` / libc++ 符号都对不上）。从官方 OTA 只取 recovery 分区（`take_partition.py` 按 Range 取 50 个 blob），换成 OS4 底包后 libs 同代，WLAN 才能继续。

### 4.2 为什么 AIDL 用 shim，而不是改 servicemanager

真机证据：`AServiceManager_addService("android.hardware.wifi.supplicant.ISupplicant/default")` 返回 `-129`（`binder_status.h` 的 `EX_TRANSACTION_FAILED`），supplicant 在打开 per-interface socket 前退出。recovery 的 servicemanager / VINTF 不认这个 vendor AIDL 服务；Skyward 只用 per-interface `SOCK_DGRAM` control socket，不需要 AIDL 真的可用。shim 只覆盖这一个符号，风险局限在 supplicant 进程。

### 4.3 为什么振动不用 FF

AW8697 的 FF 接口接受的是 Awinic 的 RTP / 自定义波形（`custom_wave`、`period_size`），不是 qcom 的裸 i8 采样。直接写 sysfs 的 `activate` / `duration` / `gain` 最稳，也能复用设置页滑杆。

### 4.4 为什么锁屏和自动解密这样接

`ui::run` 原本先 `App::new(first)` 再读 settings；改成先读 settings，若 `Menu` 且存在锁屏则 `first = Lock`，否则 `Decrypt`。`App::arrive()` 在首帧触发 `OpenData`，所以「首屏自动解密」不需要额外 effect；锁屏成功后才把栈换成 `Decrypt` 并 `open_data()`。

### 4.5 为什么 Skyward 更新要改版本

上游 `github.rs` 硬编码 `kirklin/skyward`，而 onyx 的资产在用户仓库；版本比较用 `semver`，`0.2.0` 与 `0.2.0-onyx.4` 的前者更大。把 workspace 版本改成 `0.3.0-onyx.1`、tag 与资产名都跟随，才能正确判断「有更新」。

## 5. 踩过的坑

1. **Windows 上 `Path::is_absolute` 不认手机路径**
   - 现象：`[wlan] firmware: /vendor/... is not an absolute path`，宿主打不了镜像。
   - 根因：Windows 的 `Path::is_absolute` 需要盘符 / UNC，`/vendor` 不算。
   - 解法：手机侧路径改用 `has_root()`；`[[owners]]`、`[haptics].resonance`、`[wlan] firmware` 都改。
   - 预防：所有「手机上的绝对路径」校验都用 `has_root`，不要用宿主语义。

2. **vendor AIDL supplicant 在 recovery 里注册失败**
   - 现象：supplicant 打 `Starting AIDL supplicant` 后立刻 `Failed to initialize wpa_supplicant`；LD_PRELOAD 探针显示 `addService -> -129`。
   - 根因：recovery 的 servicemanager/VINTF 不认 vendor 的 AIDL 服务；不是库缺失。
   - 解法：`shim/wpa-aidl-shim.c` 把 `AServiceManager_addService` 应答为 0。
   - 预防：换 vendor / 换 supplicant 后先看这个返回值；不要先怀疑权限。

3. **wlan0 出现后立刻 `set_up` 报 EBUSY**
   - 现象：`bring wlan0 up: Device or resource busy (os error 16)`，FW 仍在初始化。
   - 根因：接口节点先出现，驱动还没准备好。
   - 解法：`bring_up` 对 `iface::set_up` 重试 10 秒（200 ms 一次）。
   - 预防：任何「设备节点出现」都不等于「可用」，要留重试。

4. **自动连接把密码写空**
   - 现象：第一次自动连接成功，但 settings 里 `wlan.password` 变成 `""`；下次启动密码丢失。
   - 根因：`set_wlan` 保存时只取 `state.wlan_password`，自动连接路径没有「用户刚输入的密码」。
   - 解法：保存时优先用 `wlan_password`，否则沿用同一个 SSID/名字的已存密码。
   - 预防：自动连接和手动连接共用保存路径，写测试覆盖「没有新密码时保留旧密码」。

5. **OS4 vendor 的 `wpa_supplicant` 与 OS3 recovery 的 libs 错位**
   - 现象：`cannot locate symbol "_ZNSt3__113__hash_memoryEPKvm"`、`libvndksupport.so` / `libdl_android.so` 找不到。
   - 根因：recovery 是 OS3，vendor 是 OS4；`/vendor/lib64/libc++.so` 比 `/mnt/system` 的旧。
   - 解法：换 OS4 底包；`[wlan].libraries` 用 `/mnt/system/system/lib64/bootstrap`、`/mnt/system/system/lib64` 优先，再 vendor / recovery。
   - 预防：底包与 vendor 必须同代；升级系统后重新对 recovery 底包。

6. **AW8697 的 FF 波形格式不是 qcom 的采样**
   - 现象：现有 FF 路径在 qcom 上工作，在 onyx 上不产生振动。
   - 根因：AW8697 的 `FF_PERIODIC` 自定义数据要 Awinic 的 RTP / waveform 格式。
   - 解法：新增 sysfs 后端（`activate` / `duration` / `effect_id` / `gain`）。
   - 预防：先查 `/sys/bus/i2c/devices/*` 和 `/proc/bus/input/devices`，不要假设 FF 通用。

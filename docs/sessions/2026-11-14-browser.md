# 2026-11-14 · 下载页改成图形浏览器

> 对应版本：`v0.3.0-onyx.4`（镜像 SHA-256 `239d0fbb…f3ea`）

## 用户要的

1. 「下载」改成浏览器，下载集成在浏览器里；
2. 要图形界面，能加载 `bing.com` 的全部内容，包括图片；
3. 还要能上看 `bilibili.com`；
4. 也要能上原神等官方网站并加载/渲染；
5. 「关于本机」的「© 2026 Kirk Lin」改成「© 2026 Kirk Lin & Remoparrot」；
6. 下载用上 Skyward 更新那套 512 并行的速度；
7. 搞好后刷入现在在用的 Skyward、同步到 GitHub。

## 做了什么

### 1. 自带的小排版引擎（`crates/skyward-ui/src/web/`）

| 文件 | 内容 |
| --- | --- |
| `html.rs` | 容错解析：未闭合标签按语义闭合（`p`/`li`/`td`/`tr`/`option`/`a`）、void 元素、`script/style/title` 原文、属性（带引号/裸值）、常用实体与数字实体 |
| `css.rs` | 选择器（标签 / `.class` / `#id` / 后代 / `>`）、特异性级联、内联 `style`；属性子集：display、颜色、背景色、字号、粗细、对齐、margin / padding、行高、列表、宽度、下边框；一套接近浏览器的默认样式 |
| `layout.rs` | 块级堆叠 + 行内片段成行：按词与 CJK 逐字断行、超长词按字符断、图片作为行内原子、列表项目符号、图片按容器宽度缩放；输出带绝对坐标的绘制项和链接命中矩形 |
| `image.rs` | PNG / JPEG / WebP / GIF 解码（`image` crate，最长边 1,024），双线性缩放绘制 |
| `mod.rs` | 取页（`ureq`，8 MB 上限）、字符集（GBK 等）、相对 URL 解析、并发取图（8 线程、最多 64 张）、SPA 兜底摘要、`Page` 的分段绘制 |

浏览器页本身在 `pages.rs`：下载卡、地址栏、前往/下载/后退/刷新、状态行、link.txt、二维码、编辑态键盘，以及网页内容的绘制与链接命中；`app.rs` 里是状态与动作，`skyward/src/ui.rs` 里是后台读取线程。

### 2. 只由脚本生成的页面

`ys.mihoyo.com` 这类页面正文靠 JS 生成，HTML 里只有标题和 description。读取完发现可见文字不足 60 个字符且没有图片时，改用页面自报的信息重排：`<title>`、`meta description`、`og:image`、内联 `<style>` 里的图片、页面里的链接。原神官网因此能显示标题、版本简介和官方图片，而不是白屏。

### 3. 浏览器里的下载

- 地址栏「下载」直接下载输入框里的 URL；页面里点到非 HTML 的响应（图片、zip、img…）自动转为下载；
- 下载卡在浏览器页顶部：网速、暂停/继续、停止、完成后的路径；
- `skyward-net/download.rs` 新增 `save_fast`：`Range: bytes=0-0` 探长度 → 支持分段就复用更新那套「64 KiB 分段、最多 512 连接」；不支持就退回 `save` 单连接；暂停标志也在并行循环里生效。

### 4. 顺手修的

- `browser_loaded` 返回的后续动作（如「是文件，开始下载」）原来被丢掉，现在经 `Incoming::Fetched` 进入主 effect 队列；
- `pages.rs` 里列表项只有「不含块级子元素」时才画项目符号（搜索结果那种 `<li><h2>…</h2></li>` 不再顶一个圆点）；
- 导航条（`<nav>`）里的 `ul/li/a` 按行内排，不再竖着堆；
- 关于本机署名改为「© 2026 Kirk Lin & Remoparrot」。

## 已知限制

- **不运行 JavaScript**，且只做了块排版（没有 flex/grid）：脚本应用类页面只能看静态内容；B 站播放器、Bing 首页动效、原神官网动效都不能用；视频/WebGL 不支持。
- 不取外部 CSS 样式表，所以版式与真实浏览器差别很大（偏「阅读模式」）。
- 二维码回传的 URL 偶尔被截短（8080 页面只读一次请求头），地址栏输入不受影响。
